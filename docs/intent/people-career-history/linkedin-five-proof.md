# Five-profile LinkedIn import proof

Completed November 11, 2026. Read five existing contacts' Experience sections in the user's signed-in Chrome session. Saved the result through Visual Notes MCP. No application code changed.

## Result

The five profiles supplied 41 role records: 9, 6, 12, 8, and 6 respectively. The histories include company, title, start month, end month or Present, location where shown, and selected responsibility details. Source URLs and the check date are stored with each row. Promotions, concurrent roles, gaps, and repeat stints at an employer were preserved.

These fields are separate collection properties in [People Career History](https://notes.apps.byroni.us/collections/cmwd1irgz04p7qp215dja9c69). Start and end months use `YYYY-MM` text. They are not converted to invented calendar days.

Each People profile now links to its own career-history note. Each note embeds a filtered, newest-start-first table of that person's roles. The five notes belong to People Source Archive. Both collections exclude their individual rows from Recent. Five sourced current-role facts also make the new evidence visible in the People memory section. Existing summaries were updated with useful professional context.

## Proof and limits

- Queried all 41 saved rows and compared person, company, role, and both month values with the captured source data.
- Verified the five filtered histories return 9, 6, 12, 8, and 6 rows.
- Read back the profile links and confirmed contact dates were unchanged.
- Checked collection settings and all five embedded view references.
- Opened the nine-role history in Chrome and confirmed its table renders. The sidebar shows ordinary recent notes and the collections, rather than individual source rows.
- Compared the captured periods and recorded one shared-company lead: two people list overlapping Allison employment from June 2017 through July 2019. This is a possible connection, not a verified acquaintance.

The live LinkedIn profiles solve the source-data gap for this five-person sample. The earlier official connection export did not contain these histories. Manual authenticated browsing is now a proven acquisition path; ongoing automatic synchronization is not part of this result.

The collection is a working bridge, not a replacement decision for the People model. The 41 roles were not inserted as undated native affiliations. The native model still cannot preserve their month precision, independent employment status, and role sources correctly. The People profile itself still needs the requested Experience timeline and overlap query. It can later import these structured rows instead of collecting the information again.

Do not treat two current entries under related employer names as two separate jobs without review. Do not merge employer labels or infer company renaming from names alone. Preserve the displayed source entries until organization identity is resolved.
