## What this matrix does not call missing

Sticky headers and row identity, width resize, property reorder/hide, filters/sorts/search, bulk edit, windowing, four view types, full-note peek and body-save protection already exist. The gap is how these features combine in constrained space and how clearly they distinguish reading, editing, configuration and durable saves. For example, Gallery is already available, but its unlabeled fields, omitted empty values and cover defaults do not make it an automatic replacement for mobile review.

## Work grouping and dependencies

1. **Correct keyboard/validation behavior:** CU-05, CU-19, then CU-10 and CU-18. These can improve the current table before a new layout ships.
2. **Make record review complete:** CU-03 and CU-04 before investing in CU-14's next/previous flow. Preserve the existing body-save guard; investigate CU-09 with controlled failures.
3. **Make responsive layout coherent:** CU-01, CU-02 and CU-07 together. A shorter view strip alone does not fix the frozen-width problem; shrinking columns alone does not fix long-text reading.
4. **Explain state and scope:** CU-08, CU-15, CU-16 and CU-17. Preserve data guarantees while making persistence/configuration visible.
5. **Finish alternate views/input:** CU-06, CU-11, CU-12 and CU-13, using actual touch and keyboard tests before claiming accessibility conformance.

Priorities are audit recommendations, not promised delivery dates. Integration-risk findings must be reproduced before they become confirmed production defects. See [reassessment](reassessment.md) for proof required to close each node.
