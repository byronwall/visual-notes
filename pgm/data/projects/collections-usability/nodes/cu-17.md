# CU-17 Reflow collection creation and note-import forms

**Priority:** P2 · **Evidence:** Source risk; browser dialog test required · **Baseline:** `25c7a864947994b8f321ceab73e6b8eae14e3107`

## Current behavior

CollectionsIndex places heading and creation form in a non-wrapping header; the name field has minW 14rem. AddNotesDialog puts two search inputs in one flex row without explicit minW 0 on the inputs. Both can encounter narrow available width.

## User impact and gap

The feature must be usable before a table exists. A mobile user may have difficulty naming a collection or finding/importing an existing note; long collection names and the software keyboard further reduce space.

## Reproduce

1. At 320 and 390px start New collection from a non-empty index.
2. Open Add notes with a long collection name and focus each search input.
3. Select notes, filter the list, cancel/reopen and inspect the selection count; include a note from another collection.

## Likely ideal and proposed work

Stack forms and secondary filters when space is limited, provide a visible cancel path, retain draft/selection only when intended, and explain move/value mapping before committing existing-note moves. Verify actual conversion behavior instead of assuming note content is lost.

## Acceptance and reassessment

- [ ] Creation and import controls fit at 320px and with a mobile keyboard.
- [ ] Visible selection and submit count stay understandable across searches and reopen.
- [ ] Moving from another collection explains affected membership and any values that will not map; note bodies remain intact.

Run R16 in the [reassessment protocol](../../../../../docs/intent/collections-usability-audit-2026-11-11/reassessment.md). Record fixed commit, browser/device, before/after screenshots and test result. A source hypothesis becoming confirmed is a status/evidence update, not automatically a fix.
