# CU-06 Make rating and secondary targets comfortable and semantic

**Priority:** P1 · **Evidence:** Source verified; browser follow-up required · **Baseline:** `25c7a864947994b8f321ceab73e6b8eae14e3107`

## Current behavior

This finding concerns the separate numeric rating format (`RatingStars`). The review fixture uses a select property named Rating; the numeric-star behavior was source-reviewed, not exercised in those screenshots.

RatingStars renders unpadded text-glyph buttons with a 2px gap, inside a radiogroup without radio roles or aria-checked on the buttons. Property reorder/hide and link-open controls are also compact. Many toolbar controls are 28px high; small does not automatically mean a WCAG failure.

## User impact and gap

Rating is a frequent review action but requires precision on a phone. Announced radio-group state is incomplete. Small adjacent controls raise mis-tap risk in property menus on both touch laptops and phones.

## Reproduce

1. Measure actual bounding boxes and center-to-center spacing for stars, link-open, property hide/reorder, clear-search and row selection.
2. Use keyboard and a screen reader to set, change and clear a rating.
3. Repeat with coarse pointer and at 200% zoom.

## Likely ideal and proposed work

Use clear selected state and a valid radio-group or equivalent native input pattern. Increase primary touch review controls to a 44px comfort target. Verify the actual WCAG 2.5.8 24px size/spacing rule including exceptions before making a conformance claim.

## Acceptance and reassessment

- [ ] Rating choices expose labels and checked state, arrow navigation and a clear/unrated action.
- [ ] Primary mobile targets meet the agreed 44px comfort goal; other targets meet AA size/spacing or a documented exception.
- [ ] Visual density on laptop remains useful without requiring precise glyph clicks.

Run R06 in the [reassessment protocol](../../../../../docs/intent/collections-usability-audit-2026-11-11/reassessment.md). Record fixed commit, browser/device, before/after screenshots and test result. A source hypothesis becoming confirmed is a status/evidence update, not automatically a fix.
