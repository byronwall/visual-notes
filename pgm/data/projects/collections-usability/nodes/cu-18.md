# CU-18 Expose keyboard and touch alternatives for column sizing

**Priority:** P2 · **Evidence:** Source verified capability gap · **Baseline:** `25c7a864947994b8f321ceab73e6b8eae14e3107`

## Current behavior

TableHeaderCell resizes with a 6px-wide pointer separator and resets width on double-click. The separator has an ARIA label/orientation but is not focusable and has no keyboard handler. Property reordering already has up/down buttons in PropertiesMenu, so reordering is not exclusively drag-only.

## User impact and gap

Column widths are the current escape hatch for difficult tables, yet resizing is difficult on touch and unavailable through this keyboard control. A 6px handle alone is not a reliable mobile fix.

## Reproduce

1. Tab to the Name resize control and attempt keyboard resizing.
2. Resize on a coarse-pointer phone without activating the property menu.
3. Compare with existing keyboard property reorder controls.

## Likely ideal and proposed work

Provide accessible keyboard resize semantics or a column-width menu with presets/numeric values and reset/fit options. Preserve direct pointer resizing for laptop efficiency, with generous touch hit areas that do not collide with adjacent headers.

## Acceptance and reassessment

- [ ] Keyboard and touch users can change/reset width without dragging a tiny edge.
- [ ] Resize announces or visibly reports the new width and obeys bounds.
- [ ] Column resize, property menu and reorder remain distinct actions.

Run R02 R06 in the [reassessment protocol](../../../../../docs/intent/collections-usability-audit-2026-11-11/reassessment.md). Record fixed commit, browser/device, before/after screenshots and test result. A source hypothesis becoming confirmed is a status/evidence update, not automatically a fix.
